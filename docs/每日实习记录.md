## 2026年8月31日

**当日主题：** 智能体（Agent）开发课程：Agent、Skill 与 Script/CLI

**主讲人：** 杨震

本次课程首先区分 Chatbot 与 Agent：前者侧重一次性回答，后者以可验证任务为目标，通过理解、行动、观察和迭代形成闭环。学习了 ReAct 的 Reason、Act、Observe 最小循环，并认识到 Agent 的稳定性不仅取决于模型，也取决于权限、沙箱、日志、记忆、错误处理和工具管理等 Harness Engineering。
课程重点讲解 Agent、Skill、Script/CLI 三层架构：Agent 负责理解与编排，SKILL.md 规定触发条件、参数、步骤、失败策略和结果校验，脚本承担确定性执行。开发应遵循“先工具后 Agent”，先定义输入输出、完成脚本和异常测试，再封装 Skill、接入自然语言联调。CLI 必须使用参数传值，stdout 仅输出 JSON，stderr 输出诊断，退出码区分成功失败。
安全方面遵循最小权限、显式确认、秘密隔离、可审计和失败安全，严禁硬编码密钥与未经确认的破坏性操作。通过个人文件模糊搜索案例，我理解了分层检索和低 Token 策略，也明确本次项目需满足场景、Skill、脚本、自然语言、异常处理、测试样例和 Demo 七项验收标准。
课程中我进一步梳理了 Agent 不稳定的常见来源，包括循环调用、目标漂移、失败难恢复、上下文噪声、工具接口不统一和缺少结果验证。结合本次 PDF 课题，我将这些问题转化为具体约束：每次只执行一种页面操作，Agent 不直接读写 PDF，Script 返回固定 JSON，失败时保留原文件，并用测试重新打开输出验证页数和顺序。个人文件模糊搜索案例也给了我启发，即处理流程应遵循先低成本后高成本、命中即停止、限制候选数量的原则。对应到 PDF 项目，就是先让规则解析常见指令，只把操作名、文件名、页码和统计摘要放入上下文，避免上传文件全文。当天课后我根据七项验收标准建立了检查表，并将任务分成核心脚本、Skill 封装、Agent 接入、测试安全和文档演示五部分。通过本次学习，我认识到智能体不是单纯聊天界面，而是受权限、协议和验证机制约束的行动系统；后续开发必须先证明工具正确，再讨论提示词和路由效果。

## 2026年9月2日

**当日主题：** CLI 契约与页码规则设计

**主讲人：** 无（项目自主实践）

设计成功和失败 JSON 字段，明确 stdout、stderr 与退出码职责。实现从 1 开始的页码语义，支持单页、逗号列表和连续范围，仅在访问 pypdf 页面数组时转换为从 0 开始的索引。同步考虑非法字符、零、负数、反向范围和越界等异常。当天认识到稳定接口比单次运行成功更重要，Agent 必须依靠固定契约而不是解析自由文本。
我把页码解析独立为纯函数，先按逗号拆分各片段，再识别单页与连续范围，最后结合文档总页数进行边界检查。这样既能处理“二到四页”对应的二至四范围，也能支持一、三至五等组合。调试时重点验证了零页、负数、字母、反向范围、重复页和末页等情况，发现若把用户页码过早转换为零基索引，错误消息会出现难以理解的偏差，因此决定对外始终保存从一开始的页码，仅在访问 reader.pages 时减一。输出契约方面，我规定成功结果包含状态、操作、输入输出文件、处理页码、输出页数和简短说明；失败结果包含固定错误码和可读消息，诊断只写入标准错误。为了避免 argparse 参数缺失时破坏契约，我计划后续重写其错误出口。当天还用小型样例手工推演了五个命令，确认参数中不包含硬编码路径。通过这项工作，我体会到接口设计应先于功能堆叠，稳定语义可以显著降低 Agent 联调复杂度。
我还记录了命令行调用示例和预期 JSON，分别模拟成功、越界与参数缺失。通过对比发现，错误消息既要让用户理解，也要让 Agent 依靠 error_code 稳定分支，不能只返回一段变化较大的自然语言。下一步将先完成 Script，再用这些样例回归。

## 2026年9月4日

**当日主题：** pypdf 核心功能开发

**主讲人：** 无（项目自主实践）

使用 pypdf 完成页面提取、删除、合并、排序、倒序与旋转。删除操作通过构造保留页集合实现，合并允许每个输入指定独立页码，重排要求原页面每页恰好出现一次。针对删除单页文档唯一页面的情况增加拒绝逻辑。采用同目录临时文件写入后替换的方式，避免异常中断留下不完整输出。
开发时先建立统一的 PdfReader 与 PdfWriter 使用流程。提取操作按解析后的页码依次加入 writer；删除操作计算原页面集合与待删页面的差集；合并操作逐个打开输入并按各自页码追加；重排操作按照用户指定的完整序列复制；旋转操作仅修改目标页的旋转属性，其余页面原样保留。调试中发现删除单页文档唯一页面虽然在逻辑上可执行，却会得到无意义的空文档，因此增加 NO_PAGES_REMAIN 错误。另一个问题是写文件过程中断可能留下半成品，我改为先写同目录临时文件，成功后再原子替换目标。对输出已存在的情况默认拒绝，避免测试或重复命令静默覆盖。当天用不同尺寸的空白页进行手工检查，确认倒序和自定义排序确实改变了页面来源，而不只是输出页数正确。完成这些实现后，五项核心功能可以在不经过 Agent 的情况下独立运行，为下一阶段封装 Skill 奠定了稳定基础。
完成代码后，我逐个比较输入文件与输出文件的页面数量，并确认原文件修改时间和内容保持不变。对于输出目录不存在的情况，仅在允许目录内部创建必要父目录；若路径越界则在写盘前终止。当天把操作函数保持为清晰分支，避免过早抽象影响调试。

## 2026年9月7日

**当日主题：** 异常处理与路径安全

**主讲人：** 无（项目自主实践）

补充文件不存在、非 PDF、空文件、损坏 PDF、加密 PDF、页码越界和输出已存在等错误处理，并统一为固定 error_code。加入 allowed-dir 目录白名单，对规范化后的输入输出绝对路径进行归属判断，阻止使用上级目录符号越界访问。默认输出新文件且禁止覆盖原文件，使失败可控、无副作用。
异常处理采用统一 EditorError 类型，把底层文件系统和 pypdf 异常转换为 FILE_NOT_FOUND、NOT_PDF、EMPTY_FILE、INVALID_PDF、ENCRYPTED_PDF、PAGE_OUT_OF_RANGE 等固定错误码。对于加密文件，即使可能存在空密码也直接拒绝，因为本项目没有设计密码授权和保管流程。路径校验方面，我没有使用字符串前缀判断，而是先解析规范绝对路径，再判断它能否相对于允许目录表示，从而拦截上级目录符号、绝对系统路径和名称相似的旁系目录。输入文件和输出文件使用同一套边界检查，防止从允许目录读取后写到外部位置。日志采用允许字段清单，只写 UTC 时间、操作类型、文件基名、状态和错误码，不记录绝对路径、自然语言原文、确认令牌或环境变量。当天通过伪 PDF、空文件和越界路径逐项验证，确保失败返回非零退出码、stdout 仍是 JSON、原文件没有变化。此次工作让我认识到安全不是最后补充的说明，而要体现在每一条失败路径中。
为了验证日志脱敏，我查看生成记录，确认只出现文件基名而不包含完整用户目录；同时检查异常消息不会暴露 Python 调用栈。随后用相似目录名和多层上级路径测试归属判断，结果均被拦截。下一步将在 Skill 中把这些安全前置条件写成明确步骤。
当天将新增错误码逐项登记到说明文档，保证名称、触发条件和用户提示一致。复盘后确认所有校验都发生在创建输出文件之前。

**主讲人：** 无（项目自主实践）

编写 SKILL.md，明确提取、删除、合并、排序、倒序与旋转的触发场景，以及 OCR、内容编辑、解密等不适用范围。文档列出参数格式、安全调用顺序、成功与错误 JSON 示例。将复杂确定性逻辑留在脚本中，使 Skill 保持精简，降低 Agent 读取时的上下文开销。
编写 Skill 时，我先定义触发边界：只有提取、删除、合并、排序、倒序和旋转这类页面级操作才应调用该能力；文字修改、OCR、签名、解密和表单填写必须明确拒绝或交给其他工具。随后整理五个子命令的参数示例、页码格式、覆盖规则、错误码和 JSON 结果，使 Agent 不需要阅读脚本源码即可正确调用。为了控制 Token，我没有把所有实现细节堆入 SKILL.md，而是保留最关键的选择规则、安全顺序和结果判断。联想到课程中“Script 解决怎么做，Skill 解决何时做和做完怎么办”的原则，我特别增加了调用前展示计划、确认后执行、失败时依据错误码回复的步骤。检查过程中发现合并的 page-specs 必须与输入文件一一对应，于是在文档中明确 all 代表全部页面，并说明数量不匹配时返回错误。当天用五条自然语言例句反向检查 Skill 描述，确认每条都能映射到唯一子命令和参数组合。
文档完成后，我从一个不了解源码的调用者角度重新阅读，检查是否能仅凭 Skill 选择正确命令并判断结果。对于页码从一开始、输出不得覆盖和确认令牌等容易忽略的事项使用明确语句提示。最终保证说明精简但信息闭合，为 Agent 路由测试做好准备。
我同时检查示例命令中的全局参数位置和子命令顺序，确保复制后可直接运行。对不适用场景给出边界说明，防止 Agent 错选工具。

实现轻量 Agent 的动作分类、PDF 文件名提取、中文页码范围和旋转角度识别。对于缺少文件、页码或角度的不明确请求，返回 INTENT_NOT_UNDERSTOOD，不进行猜测。五条典型自然语言指令均可转换为确定参数，Agent 只负责语言与编排，不直接修改 PDF。

完成后把解析结果与手工预期逐字段比较，包括操作名、页码、角度、输入和输出。所有测试均先预览，不直接触发文件写入。

**当日主题：** 执行前预览与确认机制
